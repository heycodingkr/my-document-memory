# Landing, README and main-feature smoke audit review

Date: 2026-11-09. Contract: [specification](../spec/landing-readme-smoke-audit-v1.md). Evidence: [inputs and results](../test/landing-readme-smoke-audit-v1.md).

## Findings and root causes

1. The README described the vision and background for many screens before the hosted quick start and current runtime limits. This made the actionable entry point and the distinction between template-based outlines and model-written drafts harder to find. Added hosted app/public-template links and a short current-capability paragraph at the top; retained the existing product direction and benchmark qualifications.
2. README verification commands emphasized runtime-only browser checks. Account/review specs deliberately skip without the synthetic mailbox fixture, so that command alone is insufficient evidence for account/community behavior. Added fixture build dependencies, separate account/community/recall commands and a coverage table; explicitly separated Python-double results, real Rust results and read-only deployment checks.
3. Issue #393 described a formerly private source repository. Anonymous GitHub access now works; the old premise is historical (BCB #53638 independently agrees). The landing still displayed a GitHub-access warning in both languages. A fresh pre-edit setup screenshot reproduced the confusing copy; replaced only those notes with hosted no-install guidance and source-build prerequisites. The post-edit screenshot was opened and inspected. Existing language/setup/link tests passed; no new tests were added for the reversible copy-only change.
4. The hosted smoke failed twice at different network stages: first waiting for the HTTP health redirect, then during TLS negotiation while comparing email-auth configuration. Separate probes between attempts returned the correct 308/200 responses in under 0.6 seconds. This is consistent with the existing intermittent latency report #409, but does not establish a server-side root cause. Recorded the evidence in that issue; did not change production or relax test timeouts to manufacture a pass.
5. `cargo fmt --all --check` reported formatting differences in 21 files, primarily concurrent web-memory integration plus review/queue edits. Runtime tests/builds passed. Registered #410 for the formatting gate and left other sessions' Rust edits untouched.
6. A later source/build integration exposed a new contribution fixture mismatch. `/me/contributions` now requires a registered member, while the account fixture's CLI/MCP bearer owners are `local` and `bob` without member records. The last account run passed 10 cases and failed MC-12/13 at submission setup with401; community smoke failed a valid rights-confirmed CLI submission with `auth_required`. The signed-in-member AC-18 flow still passed. Registered #411 rather than weakening authorization or rewriting another session's member policy. The final Rust 113-test pass preceded subsequent shared source edits; it cannot certify them. Earlier all-pass browser/community runs are retained as historical evidence, not the final verdict.

## Review and boundaries

Changes are limited to README entry points/verification instructions and two landing copy values, plus this audit's specification/results/design documents. Git was already heavily dirty and main was behind origin; no reset, pull, staging, commit, publication or deployment was performed. All verification was run by the parent, with no delegated summary used as evidence.

The fresh desktop hero and setup screenshots were inspected. A useful next product-copy improvement is a prominent direct free-template action in the hero: its primary action currently scrolls to the getting-started section, while public browsing sits in the navigation. The hosted web setup also places a local clone command in a large code panel; consider collapsing local setup separately so the hosted path is easier to scan. These are recommendations, not implemented behavior changes.

Smoke coverage is bounded: temporary databases and synthetic email capture, actual Rust CLI/MCP/HTTP and Playwright browser behavior. It does not prove live inbox delivery, model quality/savings, native Word/PowerPoint layout, external-provider editing or full Arise browser integration. This audit made no production writes.
