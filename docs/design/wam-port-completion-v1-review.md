# WAM 포팅 보완: 설계·원인·리뷰

날짜: 2026-11-09. 계약은 [`../spec/wam-port-completion-v1.md`](../spec/wam-port-completion-v1.md), 입력·기대 결과는 [`../test/wam-port-completion-v1.md`](../test/wam-port-completion-v1.md).

## 초기 관찰과 원인

기존 포팅은 핵심 계약, 플랫폼 명세, 238개 블랙박스 케이스, 131개 하네스 자체 검사와 18개 변이를 이미 갖췄다. WAM의 `docs/spec` 31개는 모두 같은 이름의 대상 파일이 있다. 그러나 포팅 표·색인·환경 기록은 초기의 제품 없음/CLI·MCP 없음/플랫폼 문서 작성 대기 상태를 계속 현재 상태로 설명한다. WAM `metrics.md`와 호스트별 차이도 아직 명시적으로 대응하지 않았다. 목록 완전성을 검사하는 실행 가능한 게이트가 없어 새 원본이나 누락 파일을 추적할 수 없다.

초기 `doctrace --all`은 GP 범위 인용에서 실제 정의되지 않은 17개 ID를 검출했다. 하네스 자체 검사는 131개 통과했다. Rust 전체 기준선은 다른 세션의 관리자 이메일 구현 테스트 3개가 실패했다. #402에 정확한 파일과 실패를 기록했으며, 이 포팅에서 다른 세션의 구현을 덮어쓰지 않는다.

## 설계

원본 전체에 한 행씩 처분을 기록하는 별도 manifest와 작은 정적 검사기를 둔다. 문서 존재를 기능 구현 완료로 해석하지 않는다. 원본·대상 내용의 대응은 직접 리뷰하고 manifest 검사는 누락·잘못된 경로·처분·대상 파일을 잡는다. 검사기 자체는 합성 트리의 정상·결함 대조군으로 먼저 실패를 재현한 뒤 구현한다.

## 최종 리뷰

1. 직접 파일 집합 대조: WAM Markdown 명세 31개·테스트 62개 모두 manifest에 한 행씩 있다. 적응 72·제외 21이며 모든 대상 파일이 존재한다. 수집 자식 #166의 파일 수에는 다른 종류 파일도 포함되어 있어 그 개수를 그대로 쓰지 않았다. 인용 원본과 대상은 직접 열어 확인했다. 새 metrics·사전 등록 양식·호스트 매트릭스가 누락을 채운다.
2. 실제 코드/계약 분리: `dmem-cli/src/main.rs`, `dmem-mcp/src/lib.rs`, recall·community 스모크와 실행 로그를 직접 읽었다. 실제 `document_*`와 전체 목표 `doc_memory_*`의 차이를 유지한다. 최초 runtime 단계의 인증·공개 기여 없음 설명은 후속 계약의 확장을 명시한다. 나머지 목표 명세의 상태 머리말도 색인의 실제 구현 단계와 구분했으며, 캐시·성공 사용 점수 설계와 현재 recall·승인당 20점 리더보드의 차이를 명시했다. 전체 목표의 미구현 영역을 제품 통과로 세지 않는다.
3. 검증: 하네스 138개, 더블 235 PASS·3 SKIP·실패 0, 변이 18/18(대조군 25개 ×2), Rust 92개·빌드, 실제 runtime·recall 44/44·community 스모크, Arise 환경 21/21을 직접 실행했다. Arise 캡처는 이미지 도구로 확인했다. 문서/코드/포팅 추적과 이 작업 범위의 공백 검사도 통과했다. 최종 전체 diff 검사에서 다른 세션의 데모 Markdown hard break가 표시되어 의도된 줄바꿈을 보존하고 별도 기록했다. 증거 경로는 테스트 결과 문서에 있다.
4. GP 추적 결함: 과거 작업 사본에서 실행한 번호를 연속 범위로 적어 실제로 정의하지 않은 번호까지 인용했다. 정의를 조작해 통과시키지 않고 이미 있는 번호 집합으로 문장을 고쳤다. 초기 관리자 이메일 실패는 담당 #402에 남겼으며 후속 전체 테스트에서 사라졌다.
5. 반복 수정 위임 #167과 EOF 정리 #168은 작업 예산이 쓰기 금지로 분류되어 수정하지 못했다. #167 완료·#168 취소 후 terminal 실패를 수집하고 실제 파일을 다시 읽은 뒤 부모가 직접 반영했다. 자식 요약은 검증 근거로 사용하지 않았다. EOF 4건은 마지막 LF들만 제거했고 나머지 bytes의 SHA-256 일치를 확인했다. #400의 FMT-08과 diff 검사도 통과했다.
6. 범위: 이 작업은 원본·기존 미커밋 변경·사용자 서버·설정·문서·탭을 보존한다. 제품 배포·실계정 OAuth·Google UI `/copy` 검증·현재 탭 clip 구현은 수행하지 않았다. 라이브 호스트 자동 행동과 전체 웹 가져오기 구현은 별도 기능 게이트로 남긴다.
