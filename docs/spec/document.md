# DOC: 문서 편집기와 작성 흐름

상태: 전체 목표 계약(문서 우선). 실제 제품 부분집합의 구현·검증 범위는 [색인](README.md)의 단계별 명세와 구분한다. 공개 게시와 사용자 간 공유는 runtime-v1 이후 단계다.
영역 / 테스트 ID 접두사: `DOC` (케이스: [`../test/functional-document.md`](../test/functional-document.md))
기반: [`formats.md`](formats.md), [`memory.md`](memory.md), [`library.md`](library.md), [`sharing.md`](sharing.md), [`template-library.md`](template-library.md), [`runtime-v1.md`](runtime-v1.md)

## 1. 목적과 범위

편집기는 사용자가 고른 양식의 구조를 `StandardDoc` 편집 화면으로 열고, 슬롯과 확인 필요 항목을 채워 결과 문서를 만든다. 웹 구현 스택은 runtime-v1과 같이 Svelte 5, TypeScript, Vite다. 이 명세는 문서와 덱을 편집하고 저장하는 흐름을 정의한다.

작성 결과는 개인 라이브러리의 문서 산출물이며 `template`이나 `reference` 메모리를 덮어쓰지 않는다. 결과는 사용한 양식과 참고자료의 `(memory_id, version)`을 기록한다. `sheet` 구조는 `stddoc/1`에 포함되지만 편집과 계산은 후속이다.

## 2. 편집 문서

- 편집 입력은 `schema: "stddoc/1"`, `type: document | deck | sheet`인 `StandardDoc`이다([`formats.md`](formats.md) 2절).
- 문서 블록은 heading, paragraph, list, table, quote, callout, image를 순서대로 편집한다. 덱은 순서가 있는 slides, 제목, 블록과 theme를 보존한다.
- 지원 블록의 구조·순서는 저장과 내보내기 왕복에서 유지한다. 변환 손실은 `warnings[]`로 보여주며 원본과 같은 모양이라고 보장하지 않는다.
- 덱은 목차와 순서를 먼저 보여주고 사용자가 승인한 뒤 생성한다. 사용자는 생성 후 블록 또는 슬라이드의 내용을 고치고 미리 볼 수 있다.

## 3. 슬롯 채우기와 작성

- 슬롯 표식 `{{name}}`은 대응하는 `slots[]` 항목의 `type`, `required`, `hint`에 따라 입력 UI를 만든다. 이름과 타입은 [`memory.md`](memory.md) 4절 문법을 따른다.
- `{{확인 필요: x}}`는 근거가 입력되지 않은 항목으로 남긴다. 출처 없는 사실이나 수치는 만들지 않고 표식을 보존하며 사용자가 직접 보완할 수 있게 한다.
- 양식 구조·스타일과 사용자 내용은 별도 입력으로 취급한다. 참고자료 내용은 사용자가 선택한 자료에서만 가져오며, 생성 결과에 출처 버전을 연결한다.
- 필수 슬롯이 비어 있으면 저장 가능한 초안으로 표시하고 누락 이름을 보여준다. 내보내기 전에는 미완성 슬롯과 확인 필요 표식을 검토할 수 있다.

## 4. 출처와 라이선스

- 복사한 양식을 바탕으로 만든 문서는 원본 양식의 저작자, 라이선스, `(memory_id, version)`을 출처 패널에 표시하고 저장 기록에 유지한다.
- `structure_only` 라이선스의 문서 초안은 제목·순서·슬롯·스타일·표 머리글만 사용한다. 원본 본문 문장을 결과 내용으로 복사하지 않는다([`sharing.md`](sharing.md) 4절).
- 출처 표시는 내보낸 결과에도 포함한다. 사용자가 출처 표기를 지우거나 라이선스 상한을 넘기는 동작은 허용하지 않는다.

## 5. 저장과 버전 충돌

- 새 결과는 새 문서 ID와 `version`으로 저장한다. 기존 결과의 수정 저장은 `memory_id`와 화면을 연 시점의 `base_version`을 보낸다.
- `base_version`이 현재 버전과 같으면 원자적으로 새 immutable version을 만든다. 이전 버전은 보존하고 문서의 입력으로 사용한 양식·자료 버전도 함께 남긴다.
- 현재 head와 다르면 `version_conflict`를 반환하고 서버 내용은 바꾸지 않는다. 편집 중인 로컬 초안은 유지하며 사용자가 최신 버전을 다시 열거나 내용을 비교·복사한 뒤 재시도할 수 있다.
- 낙관적 동시성 규칙은 [`library.md`](library.md) 3절과 runtime-v1 동작 계약을 따른다. 저장 결과와 충돌은 각각 새 버전 번호 또는 오류 코드로 관찰 가능해야 한다.

## 6. 내보내기

- 내보내기는 [`formats.md`](formats.md) 5절의 표준 구조 변환을 따른다. `document`: Markdown, HTML, DOCX, JSON; `deck`: Markdown, HTML, PPTX, JSON이다. 손실 경고와 지원하지 않는 요소를 숨기지 않는다.
- `sheet`는 `stddoc/1` 메타데이터만 정의되어 있다. XLSX/Google Sheets의 구조 추출과 수식·검증 편집은 후속이며 완성된 시트 내보내기라고 표시하지 않는다.
- Google Docs·Slides·Sheets는 provider 경로와 권한이 formats 명세에 정해진 경우에만 대상으로 제시한다. 현재 명세의 입력 어댑터나 OAuth 미지원 상태를 직접 생성·연동 지원으로 표현하지 않는다.
- Markdown의 슬롯과 `{{확인 필요: 항목}}`은 원문 그대로 내보낸다. HTML은 허용 태그만 쓰고 사용자 입력을 escape한다. 파일 생성은 기존 파일 덮어쓰기와 심볼릭 링크 추적을 막는 formats 안전 규칙을 따른다.

## 7. 개인 정보와 공개 경계

- 사용자가 작성 과정에서 입력한 이름·연락처·계정·고객 정보와 본문은 개인 문서 내용이다. 개인 문서는 기본 `private`이며 공개 시드 카탈로그와 별도 저장·검색·내보내기 경계를 가진다.
- 공개 공유 기능은 runtime-v1 이후 단계다. 개인 문서나 생성 산출물은 공개 카탈로그로 자동 복사·동기화되지 않으며, 템플릿 공개와 문서 본문 공개는 별도 동의 대상이다.
- 추후 게시를 요청하면 게시 전 개인 정보와 비밀값을 다시 검사한다. 검사가 실패하거나 동의가 없으면 공개 쓰기는 0건이며 개인 문서와 초안은 보존한다. 공유 가능한 양식 구조만 별도 검수하여 게시하고 작성자의 개인 입력·참고자료 본문은 제외한다([`sharing.md`](sharing.md) 2~3절).
- 검수와 동의 절차, 공개 계정 기능은 현 runtime-v1 구현 범위가 아니다. 이 절은 후속 공개 단계의 경계이며 구현 완료를 뜻하지 않는다.
