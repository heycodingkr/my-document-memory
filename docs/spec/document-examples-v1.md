# 문서 메모리 활용 예시 — README와 랜딩

기준: 2026-11-09. 대상은 제품 설명과 웹 랜딩이다. 외부 서비스 연결 기능을 새로 구현하거나 배포하는 작업은 포함하지 않는다.

## 문제와 목적

README는 공유·무료 AI 문서 작성이라는 비전을 설명하지만 웹 문서 환경별 사용 모습을 보여주지 않는다. 랜딩에는 Docs·Slides·Notion의 파일 이동 경로와 예시가 있으나 Medium·네이버 블로그와 양식 기억의 역할까지 연결되지 않는다.

문서 메모리가 웹 기반 문서 환경의 양식·어조·필수 항목·출처·검토 기준을 기억하고, 연결한 AI가 그 기준으로 문서를 작성하는 제품 방향을 구체적인 예시로 설명한다. 특정 모델에 종속되지 않는 작성 기준과 현재 구현 범위를 함께 이해할 수 있어야 한다.

## 문구와 설계 판단

- 예시는 Google Docs 보고서, Google Slides 덱, Notion 프로젝트 문서, Medium 블로그, 네이버 블로그의 다섯 가지다. 각 서비스에 공식 링크와 기억할 양식·작성 요청을 제공한다.
- 모델 간 일관성은 동일한 문장을 보장한다는 뜻으로 쓰지 않는다. 기억한 목차·어조·필수 항목·근거·검토 기준을 이어 쓰는 방향으로 설명한다.
- 외부 편집기 직접 작성은 제품 방향과 연결한 호스트·브라우저 지원 범위를 밝혀 설명한다. 현재 앱에서 모든 서비스에 직접 작성·게시·동기화할 수 있다고 표현하지 않는다.
- 기존 무료 서비스 비전과 양식·자료 분리 원칙을 유지한다. 사용자가 지정한 사례를 설명하는 과정에서 외부 모델·서비스의 과금이나 지원 범위를 새로 보장하지 않는다.
- 랜딩의 기존 세 개 도구 탭, AI 선택, 요청문 복사, 연결 폼, 가이드 복귀 동작을 보존한다. 정적 사례 추가를 위한 새 상태나 인증 경로는 만들지 않는다.
- 기존 sage/forest 색과 타이포그래피에 맞춰 서비스별 사례를 읽기 쉽게 배치한다. 새 이미지나 로고 자산은 필요하지 않다.
- 동시 작업으로 README와 랜딩이 영문화되고 로그인·공개 메모리 흐름이 반영되었다. 최종 활용 예시도 현재 문서의 영어를 유지한다. 새 계정 진입 props·버튼·기존 모델/도구 예시는 보존한다.

## 최종 검토

본 변경은 정적 사례와 설명 보강이므로 이를 그대로 재진술하는 새 테스트 파일은 만들지 않았다. 기존 온보딩 시나리오를 읽고, 현재 영문 UI에서 같은 공개 상호작용과 반응형 검증을 임시 Playwright QA로 직접 수행했다. 기존 한국어 온보딩 테스트 전체 통과나 계정·API 변경의 회귀 검증을 주장하지 않는다.

- `pnpm --dir web check`: 0 errors, 0 warnings.
- `pnpm --dir web build`: 성공.
- 실제 개발 서버의 공개 랜딩에서 서비스 링크 5개, 공식 HTTPS 주소·새 탭·opener 분리 확인. 활용 예시로 이동하는 동작은 추가 API 요청을 만들지 않았다.
- Docs → Slides → Notion 키보드 탐색, Claude 선택, Slides 목차 요청문과 복사 결과 일치 확인. 클립보드 거부 시 요청문 보존과 복구 안내도 확인했다.
- 1440×1000, 1440×614, 768×1024, 390×844, 320×844에서 가로 overflow 없음. 1440×614에서 시작 버튼 전체 노출 확인.
- 데스크톱 사례 6칸(서비스 5개와 모델 간 공통 기준), 390px 사례 화면, 낮은 노트북 히어로를 실제 PNG로 열어 가독성과 배치를 확인했다. 증거는 `web/test-results/document-examples/`에 둔다.
- README의 `What My Document Memory Does` 절과 새 목차 앵커, 다섯 서비스 링크를 직접 확인했다. 동시 영문화 작업이 같은 절을 번역한 최종 내용을 보존했다.
- 공식 Docs·Slides·Notion·Medium 페이지를 읽었다. 네이버는 검색 크롤러 접근이 제한되어 별도의 자기 소유 Arise 탭에서 공식 페이지 제목과 `https://section.blog.naver.com/BlogHome.naver` 주소를 확인했다.
