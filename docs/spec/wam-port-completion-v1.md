## 2. 포팅 목록 검사 계약

`contracts/wam-port.v1.json`은 `schema_version=1`, `entries[]`를 갖는다. 각 행은 원본 저장소 기준 `source`, `disposition=adapt|exclude`, 대상 저장소 기준 `targets[]`, 비어 있지 않은 `reason`이다. `adapt`는 읽을 수 있는 대상 파일을 하나 이상 갖고, `exclude`는 대상 없이 제외 이유를 갖는다. 원본과 대상 경로는 상대 경로이며 루트 이탈·중복 source·알 수 없는 처분을 허용하지 않는다.

범위는 WAM `docs/spec/**/*.md`와 `docs/test/**/*.md` 전체다. 벤치마크·사전 등록·운영 실행 기록도 목록에 개별 처분을 남긴다. 기능 계약은 적응하고 원 프로젝트의 측정 결과·실서비스 실행 이력은 제외한다. 호스트별 설정을 검증하지 못한 경우 호스트 매트릭스에 미검증으로 남긴다.

`python3 -B -m dmtest.porttrace`는 목록·대상 파일을 검사한다. 상위 WAM 폴더가 있으면 실제 원본 파일 집합과 비교하여 누락·유령 source도 실패시킨다. 없는 환경에서는 원본 비교 미실행을 명시하며 `--require-upstream`은 실패한다. 이 검사는 포팅 목록의 완전성을 확인한다. 내용의 적절성은 원본과 대상의 직접 리뷰로 확인한다.

## 3. 의존 순서와 담당

| 단계 / route | 산출물 | 독립 확인 | 선행 |
|---|---|---|---|
| G0 / 직접 | git status·diff·코드·테스트·진행 이슈 확인, 이 계약과 입력·기대 결과 | 실제 파일 읽기 | 없음 |
| G1 / `codex:gpt-6-luna` background | 읽기 전용 WAM 대조 목록, 짧은 file:line 요약 | 인용 원본과 대상 직접 열기 | G0 |
| G2 / 직접 | 문서 추적·더블·하네스·실제 Rust 기준선 | 실행 로그, 대상·프로필 기록 | G0; G1과 독립 |
| G3 / 직접 | 누락 명세·목록·호스트 매트릭스, 포팅 검사 red→green | 결함 입력을 먼저 실행한 실패, 수정 후 통과 | G1, G2 |
| G4 / 직접 | 전체 더블·변이·실제 CLI/MCP·Arise 실행 | 증거 JSON, 종료 코드, 캡처 검사 | G3 |
| G5 / 직접 | 설계·원인·리뷰·결과·이슈 기록 | 최종 diff와 증거 대조 | G4 |

계정·기여·관리자 구현은 다른 활성 이슈와 공유 중이다. 기존 변경을 보존하고 실패는 해당 이슈에 근거를 남긴다. 운영 배포·계정 설정 변경은 이 포팅의 완료 조건이 아니다.
