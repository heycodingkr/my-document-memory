# 리더보드 조회 시간 제한 v1

2026-11-09, 이슈 #408. 사용자 증상은 리더보드가 로딩에서 멈추는 것이다.
조사 시 운영 `/v1/leaderboard`는 약 0.5초에 200과 `items=[]`, `total=0`을
반환했고, 세션 소유 Arise 탭의 DOM에서도 빈 순위 안내가 확인됐다. 따라서
현재의 빈 순위와 사용자가 경험한 일시적인 로딩 정지를 구분한다. 사용자의
원래 요청이 멈춘 네트워크 원인까지 입증한 것은 아니다.

## 의존 순서와 작업 경로

| 목표 | 경로 | 산출물 | 부모의 독립 확인 | 선행 |
|---|---|---|---|---|
| 1 조사와 재현 | 부모, inline | git 상태/관련 diff·구현·기존 테스트, 명세와 테스트 입력, 실패하는 브라우저 테스트 | 실제 HTTPS 응답 및 DOM, 수정 전 테스트 실패와 로딩 화면 | 없음 |
| 2 최소 수정 | 부모, inline | session/leaderboard 읽기의 10초 제한과 일관된 오류 | 실제 브라우저에서 지연 요청 중단·오류/재시도·빈 상태·목록 확인 | 1 |
| 3 회귀와 검토 | 부모, inline | check/build, 전용 회원 흐름, 설계·결과 기록 | 기존 인증/승인/순위 테스트와 최종 diff 직접 검토 | 2 |

범위가 알려진 두 읽기 메서드이며 설계·변경 파일·브라우저 루프·검증을 부모가
직접 담당한다. 다른 세션의 작업 트리를 보존한다.

## 동작 계약

- `Api.session()`과 `Api.leaderboard()`는 요청 시작부터 응답 JSON 읽기까지
  10초 안에 완료되어야 한다. 제한에 도달하면 해당 fetch를 중단한다.
- 세션 조회가 멈춰도 공개 `#leaderboard` 진입이 무기한 차단되지 않는다.
  인증 실패/시간 초과를 로그인 성공으로 취급하지 않는다.
- 리더보드 시간 초과는 로딩을 끝내고 `The server took too long to respond.
  Please try again.` 오류와 기존 `Retry leaderboard` 버튼을 표시한다.
- Retry는 새 요청을 보내고 실제 응답에 따라 목록 또는 0명 안내를 표시한다.
  실패를 빈 순위로 표시하지 않는다. 늦은 결과는 새 화면/요청을 덮어쓰지 않는다.
- 정상 빈 응답은 공개 기여자 0명과 기존 안내를 표시한다. 임의 기여자나 점수를
  만들지 않는다. 일반 API 실패는 기존 오류를 유지한다.
- 시간 제한은 이 두 읽기에만 적용한다. 이메일 전송/확인, 저장, 업로드, 승인,
  내보내기 등 쓰기 및 다른 API의 실행/재시도 정책을 바꾸지 않는다.
- 성공/실패 시 타이머를 정리하고 자동 재시도는 하지 않는다.

입력/기대값과 결과는 [테스트 문서](../test/leaderboard-loading-v1.md),
원인·설계·검토는 [설계 문서](../design/leaderboard-loading-v1-review.md)에 기록한다.
