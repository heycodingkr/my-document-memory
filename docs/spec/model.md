# MODEL: provider-neutral 모델 설정과 예산

상태: 설계 초안(문서 우선, 구현 없음). WAM의 structured decision·최소 권한·예산 대기를 문서 검수에 적응했다. Meta/Muse 설정과 provider별 평가 기록은 제외한다.
영역 / 테스트 ID 접두사: `MODEL` (케이스: [`../test/functional-models.md`](../test/functional-models.md))
기반: [`gatekeeper.md`](gatekeeper.md), [`queue.md`](queue.md), [`runtime-v1.md`](runtime-v1.md), [`privacy.md`](privacy.md)

## 1. 목적과 사용처

모델은 고정 규칙을 보조하는 선택 구성 요소다. 서버 정책과 검증기가 최종 결정을 내리며 모델 응답만으로 게시·저장·공개 어휘를 바꾸지 않는다. 설정된 provider가 없거나 예산이 닫혔으면 모델 호출을 건너뛴다.

모델 사용처는 세 가지다. (1) 게시 검수 agent가 문서 구조와 정책 근거를 요약하고 승인 후보·거절 후보·사람 검토 후보를 제안한다. (2) 웹 편집기의 모델 초안 생성은 runtime-v1의 양식 기반 결정적 초안 다음 단계다. runtime-v1 동작을 대체하거나 바꾸지 않는다. (3) 선택적 어휘 제안은 후보만 만들며 소유자가 확인하기 전에는 어휘를 추가하지 않는다.

## 2. 설정과 예산

설정은 provider adapter, 모델 식별자, 비밀 저장소 참조, 요청 timeout, 입력·출력 schema 버전, 기능별 활성화와 한도로 구성한다. 설정은 서버 측에서만 읽고 비밀은 요청 본문·응답·로그에 쓰지 않는다. provider별 endpoint·인증 형식은 adapter 안에 격리하고 제품 계약으로 노출하지 않는다.

각 검토는 `memory_id`와 `version`에 묶인 per-review 상한(호출 수와 정규화 token 사용량)을 갖는다. UTC 날짜별 전체 일일 예산도 별도 적용한다. 호출 전 원자적으로 예산을 예약하고, 완료 후 정규화 usage로 정산한다. 예약을 얻지 못하면 요청을 보내지 않는다. 기본 숫자는 배포 설정이며 이 문서에서 고정하지 않는다.

provider가 크레딧·쿼터 소진을 정규화해 알리면 해당 검토는 시도나 비용을 소모하지 않고 대기한다. 내구성 있는 예산 게이트를 닫아 모든 worker의 모델 호출을 막는다. provider의 재개 시각이 없으면 15분부터 연속 소진마다 두 배로 늘려 최대 1시간 기다리고, 알려진 재개 시각은 30초~1시간으로 제한한다. gate가 열릴 때 worker마다 최대 한 건을 탐침 처리한다(동시 탐침은 실행 worker 수 이하). 크레딧 복구를 확인하면 대기 요청을 접수 순으로 재개하며, 운영자 수동 재개도 허용한다(WAM 승계, 재확인 필요). 대기 중 unpublish된 요청은 취소한다.

## 3. 입력, 출력, 신뢰 경계

입력은 검수에 필요한 최소 필드, 정규화된 문서 블록, 선택된 양식·자료의 안전한 요약과 정책 버전뿐이다. 원본 URL의 query, credential, 불필요한 개인 정보, 전체 대화 기록, 모델의 숨은 추론은 보내거나 보관하지 않는다.

문서 내용, 업로드된 파일에서 추출한 텍스트, 어휘 후보, 읽기 도구의 결과는 모두 **신뢰하지 않는 데이터**다. 이들은 명령·정책·권한이 될 수 없으며 경계가 분명한 데이터 필드로 전달한다. 모델은 그 안의 지시문을 따르거나 데이터 밖으로 비밀을 내보내지 않는다. 도구 결과도 지시를 싣지 않으며, 모델이 권한을 늘리거나 도구 실행을 요청해도 실행하지 않는다.

모델 출력은 버전이 있는 JSON schema, 허용 enum과 길이 제한을 통과해야 한다. 게시 검수는 후보와 고정 규칙을 비교하고 Gatekeeper가 최종 상태를 결정한다. 초안은 사용자가 편집·저장하기 전에는 문서가 되지 않는다. 어휘 후보는 소유자 승인 전에는 검색·검수 계약에 영향을 주지 않는다.

## 4. 기록과 실패

운영 기록에는 내부 adapter 종류, 설정된 모델 식별자, schema/policy 버전, 지연, 정규화 usage, 상태 코드 범주와 결과 digest만 둔다. 원문 prompt·응답·문서, API key, chain-of-thought 또는 provider별 성능·품질 평가 기록을 남기지 않는다. 사용자가 보낸 내용은 진단 로그에 에코하지 않는다.

잘못된 설정·schema·응답은 고정 오류 범주로 처리한다. retry는 같은 `(memory_id, version)` idempotency를 유지하며 안전한 한도를 넘기지 않는다. 모델 오류·timeout·예산 초과는 fail closed다. 게시 검수는 미게시 상태를 유지하고, 편집기 초안은 생성하지 않으며, 어휘 제안은 반영하지 않는다.

## 5. 요구사항과 테스트

| ID | 요구사항 | 합격 기준 | 관련 테스트 |
|---|---|---|---|
| F-MODEL-01 | provider-neutral 설정 | 같은 검수 fixture를 두 adapter 설정에서 schema 동일 입력·출력으로 실행하고 provider별 필드가 제품 응답에 없다. | MODEL-01 |
| F-MODEL-02 | per-review·일일 예산 | 한도 직전 병렬 요청에서 예약 합계가 한도를 넘지 않고, 예약 실패 요청은 provider에 도달하지 않는다. | MODEL-02 |
| F-MODEL-03 | 크레딧 소진 대기 | 소진 응답 뒤 게이트·재개 시각이 저장되고, 닫힌 동안 호출 0건이며 재개 후 대기 검토가 처리된다. | MODEL-03 |
| F-MODEL-04 | 문서·도구 주입 방어 | 악성 지시문을 본문과 도구 결과에 넣어도 도구 실행·비밀 전송·정책 변경이 0건이다. | MODEL-04 |
| F-MODEL-05 | 기능별 사용 경계 | 검수는 후보만 내고, runtime-v1 편집기 결과는 결정적이며, 이후 모델 초안·어휘 후보는 명시 설정·사용자 확인 전 저장되지 않는다. | MODEL-05 |
| F-MODEL-06 | 개인정보·기록 최소화 | provider fixture 수신 payload와 로그에서 합성 비밀·원문 불필요 필드·숨은 추론·provider별 평가 레코드가 0건이다. | MODEL-06 |

모델의 실제 품질은 이 계약만으로 검증된 것으로 간주하지 않는다. 별도 성능 주장을 두지 않으며, 안전성·정책 판정의 독립 oracle은 [검수 명세](gatekeeper.md)와 테스트 문서가 정한다.
