# PROFILE: 공개 핸들·표시 이름·소개

상태: 설계 초안(문서 우선, 구현 없음). 공개 프로필과 계정 화면은 runtime-v1 이후 단계다.
영역 / 테스트 ID 접두사: `PROFILE` (케이스: [`../test/functional-account.md`](../test/functional-account.md))
기반: [`accounts-community-v1.md`](accounts-community-v1.md), [`privacy.md`](privacy.md), [`sharing.md`](sharing.md)
WAM 승계(재확인 필요): handle은 내부 계정 ID·이메일과 분리하고, 공개 프로필 참여는 opt-in으로 둔다.
제외: WAM의 점수·랭킹·서비스 링크는 수집하지 않는다.

## 1. 목적과 식별자

프로필은 계정 소유자가 고른 공개 핸들과 선택한 표시 이름·소개만 다룬다. 핸들 규칙은 WAM 승계(재확인 필요): 대소문자 비구분 고유값, 3~24 ASCII 영문자·숫자·`_`·`-`, 시작·끝은 영문자 또는 숫자, 예약 경로명 거부다.

## 2. 공개 범위

프로필 공개와 검색 노출은 소유자가 opt-in한다. 기본은 비공개다. 표시 이름과 소개는 각각 별도로 공개 동의할 수 있고, 기본값은 비공개다. 소개는 일반 텍스트로 저장·렌더링하며 HTML을 실행하지 않는다.

공개 게시물의 `author_handle`은 `sharing.md`가 정한 공개 attribution이며, 게시마다 필요한 `share-v1` 동의와 프로필 디렉터리 공개는 별개다. 핸들 공개를 끄면 프로필 조회·목록에서 즉시 빠진다. 기존 공개 게시물의 attribution은 임의로 바꾸지 않는다. 게시물의 핸들을 숨기려면 소유자가 해당 게시물을 비공개 전환하거나 삭제해야 하며, 이미 만들어진 복사본은 공유 계약을 따른다.

공개 프로필 응답에는 공개 허용된 핸들·표시 이름·소개 외 필드를 넣지 않는다. 이메일, 내부 계정 ID, 기기 ID, token, receipt ID, 개별 복사자 신원, 비공개 라이브러리 통계는 공개하지 않는다.

## 3. 편집과 권한

프로필 조회·변경의 소유자는 본인 세션에서 결정한다. 본문에 다른 계정 ID가 있더라도 소유권을 바꾸지 않는다. 이미 사용 중인 핸들, 예약 이름, 형식 오류는 저장하지 않고 공개 상태도 바꾸지 않는다.

표시 이름·소개 공개 변경은 설정한 필드에만 적용된다. opt-out은 공개 프로필·검색 목록에서 즉시 반영되고 캐시에도 이전 값을 남기지 않는다. 비공개 프로필의 공개 조회는 없는 프로필과 같은 not-found 결과를 낸다.
