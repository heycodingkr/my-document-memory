# 웹 소개와 시작하기 v1

작성: 2026-11-09. 범위: 기존 Svelte 웹의 첫 화면과 사용 가이드. 기존 라이브러리·편집기와 API 계약을 유지한다.

## 문제와 디자인

기존 첫 화면은 비활성 사이드바와 연결 토큰을 먼저 보여 준다. 제품이 무엇을 돕는지, AI·브라우저·문서 도구가 어떤 역할을 맡는지, 처음 무엇을 해야 하는지 설명하지 않는다.

핵심 카피는 **“모델은 달라도, 좋은 문서의 기준은 같게.”**다. Codex·Claude·Muse 등 사용자가 고른 AI에 같은 양식·근거·검토 기준을 전달한다는 개념을 설명한다. 결과 품질이 모델마다 동일하다는 보장이나 자동 연동 완료를 주장하지 않는다. Google Docs·Google Slides·Notion은 무료 플랜으로 시작할 수 있는 작성 도구의 예다. AI 이용 비용은 별도다.

기존 녹색·종이 색상과 워드마크를 유지하고, 소개 → 도구별 워크플로 예시 → 공통 작성 기준 → 3단계 사용법과 요청문 → Arise Browser → 실제 라이브러리 연결 순서로 구성한다. 예시는 실제 AI 실행 결과가 아님을 표시한다. 외부 SaaS 직접 생성·동기화와 웹 내 LLM 호출은 현재 구현 기능으로 소개하지 않는다.

| 순서 / 수행 경로 | 산출물 | 부모 독립 검증 | 선행 |
|---|---|---|---|

설계·수정·빌드·테스트·리뷰는 직접 수행한다. 경로가 알려진 소수 파일 수정이며 반복적인 대량 변경이 없어 위임하지 않는다. 다른 세션의 기존 미커밋 작업을 보존하고, 배포·DNS·계정·실사용 자료를 변경하지 않는다. 기존 개발 서버를 재사용한다.

## 동작 계약

- 비연결 상태에서 인증 없이 제품 소개와 사용법을 읽는다. 토큰 입력 전에는 API 데이터 요청을 시작하지 않는다.
- 헤더·히어로의 시작하기/사용법 링크는 존재하는 섹션으로 이동한다. 모든 외부 링크는 실제 URL과 새 탭 표시, `rel="noreferrer noopener"`를 갖는다.
- Google Docs / Slides / Notion 탭은 선택 상태와 접근 가능한 패널을 제공한다. 선택한 도구에 맞춰 예시와 요청문을 바꾸되 양식·출처·검토라는 공통 기준을 유지한다. Codex / Claude / Muse 선택은 실행이 아닌 설명용이다.
- 복사 버튼은 현재 요청문만 복사하고 성공 상태를 표시한다. 클립보드를 사용할 수 없으면 직접 선택해 복사하는 대안을 안내한다. 토큰·자료는 요청문에 넣지 않는다.
- Get started는 양식·자료 선택 → AI에 기준 전달 → 검토·내보내기의 순서를 설명한다. 실제 로컬 시작 명령과 `.env` 토큰 위치, MCP 서버와 브라우저 연결의 차이를 안내한다.
- Arise 정본은 `https://arisebrowser.com/`, 연결 가이드는 `/blog/connect-ai-agent-to-browser-mcp/`다. 링크 근거: 형제 저장소 `agent-browser/website/README.md:3`, `website/index.html:13`, 실제 가이드 HTML.
- 기존 토큰 입력 필드의 레이블·검증·세션 저장·API 연결 동작을 유지한다. 실패 시 오류와 입력을 보존하며 유효한 토큰으로 재시도할 수 있다.
- 연결된 라이브러리에서 사용 가이드를 다시 열고 돌아올 수 있다. 문서 편집 상태와 미저장 내용 보호를 보존한다.
- 작은 화면에서 가로 스크롤이 생기지 않고 버튼·탭·입력과 긴 설정 예시가 사용 가능하다. 모션 감소 설정을 존중한다.

## 검증 기록

구현 후 실제 명령 결과와 화면 검사 결과를 기록한다. 외부 사이트의 접속 성공과 애플리케이션 내부의 연동 지원을 구분한다.

동시에 다른 세션이 `web/tests/agent-handoff.spec.ts`에 아직 구현 전인 영어 UI·실제 양식별 Agent prompt 시나리오를 추가했다. 이 작업의 검증 도중 기본 전체 실행에 포함되어 완료 전 60초 제한에 걸렸다. 해당 테스트나 다른 세션 구현을 변경하지 않는다. 기존 실제 API smoke에 선택적 `--browser-spec PATH` 반복 인자를 추가하고, 기본 전체 실행은 유지한다. 이 작업은 `tests/onboarding.spec.ts`와 기존 `tests/workspace.spec.ts`를 명시해 독립된 임시 DB에서 직접 검증한다. 이 인자의 입력/기대 결과는 두 경로 지정 → 관련 브라우저 8개 실행, 인자 생략 → 기존 전체 실행이다.

- `pnpm --dir web check`: 0 errors, 0 warnings.
- `pnpm --dir web build`: 성공.
- `python3 tests/smoke/runtime-v1.py --browser --browser-spec tests/onboarding.spec.ts --browser-spec tests/workspace.spec.ts`: 8/8 통과. 실제 HTTP 인증·CLI·MCP·저장 충돌·불변 이력·재시작 영속성도 통과.
- 1440×614 화면에서 시작 버튼이 일부 잘림을 전용 테스트로 먼저 재현했다(viewport ratio 0.689). 낮은 데스크톱 화면의 히어로 여백을 줄인 후 버튼 전체 표시 테스트를 통과했다.
- 키보드 방향키·Home·End로 도구 탭 선택과 포커스 이동을 확인했다. 390×844·320×844에서 설정 펼치기, 연결 폼 접근과 가로 overflow 없음 확인.
- `web/test-results/landing-desktop.png`, `landing-laptop.png`, `landing-mobile-390.png`, `landing-mobile-320.png`를 이미지 검사 도구로 직접 확인했다.
- Arise에서 공식 홈페이지와 MCP 연결 가이드의 실제 URL·페이지 제목을 확인했다. 외부 서비스에 문서를 만들거나 계정을 변경하지 않았다.
- 기존 개발 서버 PID 68076, `http://127.0.0.1:5174/`, 로그 `/private/tmp/dmem-dev.log`를 재사용했다. 배포는 수행하지 않았다.
- 최종 코드 리뷰: 기존 GitHub 링크 보존, 연결 토큰 처리·편집 상태·미저장 보호 유지, 업로드 input의 조건부 마운트에 맞춘 반응형 참조 적용. 기존 작업을 커밋하거나 덮어쓰지 않았다.
