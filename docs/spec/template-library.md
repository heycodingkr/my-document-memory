# My Document Memory — 초기 양식 라이브러리 구성안

- 상태: 시드 카탈로그 초안 v0.1
- 목표: 자주 쓰는 문서·슬라이드 양식을 표준 구조로 미리 정의해, 앱 초기 양식 라이브러리로 넣을 수 있게 한다.
범위: 이 저장소 안의 제품 설계 자료다. 현재는 카탈로그/구성 명세이며 완성 DOCX/PPTX/Sheets 파일은 아직 만들지 않았다.

## 1. 양식 메모리 한 건의 구조

양식은 빈 파일만 저장하지 않는다. 언제 쓰는지, 어떤 정보를 물어볼지, 어떤 구조로 내보낼지, 어떤 검사를 통과해야 하는지를 함께 색인한다.

| 필드 | 설명 |
|---|---|
| template_id | 안정 ID. 예: worklog.daily.ko |
| title / summary | 라이브러리 카드 제목과 한 줄 설명 |
| category / use_cases | 업무일지, 회의, 영업 등과 사용 의도 |
| format_kind | doc, slide_deck, spreadsheet, blog |
| locale / audience | 언어, 대상 독자, 개인/팀/고객용 |
| visibility | private, workspace, public |
| owner / author / license | 원 작성자와 사용 조건 |
| source_asset / source_version | 가져온 원본 또는 생성 기반 파일의 위치와 버전 |
| structure_schema | 문서 섹션, 슬라이드 구성, 시트/열 정의 |
| style_profile | 글꼴, 색상, 간격, 페이지 설정, 테마 |
| input_schema | 작성 전에 물어볼 필수/선택 입력과 유형 |
| generation_rules | 초안 작성에 적용할 지침 |
| validation_rules | 필수 섹션, 값, 공식, 길이, 레이아웃 검사 |
| sample_fixture | 합성 예시 입력과 기대 결과 |
| review_status / version | 초안·검수·게시 상태와 불변 버전 |

원본 파일은 그대로 보존한다. 색인은 제목, 구조, 태그, 용도, 스타일 속성을 저장한다. 생성형 AI가 양식 원본을 사실 자료로 오해하지 않도록, “형식 참고”와 “내용 근거”를 서로 다른 검색 결과로 다룬다.

제품 안에서 직접 만든 양식은 내부 template_id로 식별한다. provider, doc_type, locale, region, variant, page는 필터와 양식 변형 정보다. Google Docs 링크나 원본 URL은 가져온 양식에만 선택적으로 붙이며, 앱 자체 양식의 색인 키로 요구하지 않는다.

아래 DOC/SLIDE/SHEET 번호는 시드 카탈로그 항목 ID다. 사용자에게 저장되는 template_id는 문서 종류·변형·로케일을 조합한 고정 ID로 별도 발급한다.

현재 문서 종류 어휘 초안인 [form.md](form.md)에 이미 있는 report, proposal, meeting_minutes, business_plan, resume, invoice, quote, pitch_deck, report_deck, proposal_deck, lesson_deck, budget_sheet를 사용한다. 다음 시드 ID는 해당 어휘에 추가한 뒤 구현한다: work_log, work_handover, sop, blog_article, purchase_order, project_brief, product_requirements, onboarding_checklist, company_profile, company_profile_deck, work_log_sheet, project_tracker_sheet, content_calendar_sheet. project_status는 report의 변형으로 둔다.

## 2. 양식 찾기 화면 구성

라이브러리 첫 화면은 다음 큰 카테고리를 제공한다.

- **업무 기록:** 업무일지, 주간 업무보고, 인수인계, 업무 체크리스트
- **회의와 프로젝트:** 회의록, 프로젝트 현황, 킥오프, 의사결정 기록, 회고
- **영업과 사업:** 제안서, 견적서, 발주서, 회사/제품 소개, 사업계획서
- **글쓰기와 마케팅:** 블로그 글, 사례 연구, 뉴스레터, 콘텐츠 캘린더
- **프레젠테이션:** IR 피치덱, 투자자 업데이트, 프로젝트 리뷰, 제품 소개, 교육 자료
- **스프레드시트:** 업무/프로젝트 추적, 예산, 콘텐츠 일정
- **인사와 계약:** 이력서, 온보딩, NDA, 근로·용역 계약서

각 카드에 출력 형식, 대상 독자, 예상 작성 시간, 미리보기, 작성자/라이선스, 최근 검수일을 표시한다. 검색 필터는 문서 종류, 문서/슬라이드/시트, 언어, 개인/팀/공개 범위, 산업, 복잡도다.

검색 결과는 두 묶음으로 보인다.

1. **양식 후보:** 결과 구조·스타일과 작성 입력을 보여주고, 미리보기·복사·사용을 제공한다.
2. **참고자료 후보:** 본문 내용을 쓸 근거 문단과 원본 위치를 보여준다.

양식 선택만으로 다른 사람의 문서 본문을 복제하지 않는다. 공개 양식은 명시된 라이선스에 따라 구조와 스타일만 참고하고, 복사본에는 작성자·원본·버전을 남긴다. 법률 양식은 관할 지역·검수 주체·검수일이 없는 경우 “초안/전문 검토 필요” 상태를 유지한다.

## 3. 초기 시드 양식

우선순위는 AiDocX 내부 사용 사례를 참고해 정한다. 2026-07-05에 기록한 AiDocX playbook 페이지의 최근 30일 세션 수에서 업무일지, 견적, SOP, 회의록, 계약, 인수인계, 이력서, 발주서가 상위였다. 이는 AiDocX 서비스의 방문 자료이지 전체 시장을 대표하는 수요 조사로 취급하지 않는다. 일반 업무에 쓰기 쉬운 회의·프로젝트·글쓰기 양식과 Google Slides형 덱도 함께 넣는다.

### B. 슬라이드 양식 — 첫 묶음

슬라이드는 덱 제목만 저장하지 않는다. 덱의 공통 테마와 각 장의 목적·메시지·레이아웃을 함께 저장한다. 작성 전에 목차/스토리라인을 보여주고, 승인 후 장별로 만들어 미리보기에서 넘침과 중복을 검사한다.

| ID | 우선순위 | 양식 | 슬라이드 기본 흐름 |
|---|---|---|---|
| SLIDE-01 | P0 | 스타트업 피치덱 | 표지 → 문제 → 해결책 → 제품 → 시장 → 비즈니스 모델 → 트랙션 → GTM → 경쟁/방어력 → 팀 → 재무/요청 |
| SLIDE-02 | P0 | 투자자 업데이트 | 한 줄 요약 → 핵심 지표 → 이번 기간 성과 → 계획 대비 차이 → 현금/런웨이 → 리스크 → 다음 분기 → 투자자 요청 |
| SLIDE-03 | P0 | 회사/제품 소개 | 회사 한 줄 소개 → 고객 문제 → 제품/서비스 → 핵심 효익 → 사용 사례 → 증거/성과 → 도입 방식 → 연락처 |
| SLIDE-04 | P1 | 프로젝트 리뷰/QBR | 목표 → 전체 상태 → 지표 → 마일스톤 → 성과/미달 → 리스크 → 결정 요청 → 다음 분기 계획 |
| SLIDE-05 | P1 | 교육/워크숍 | 학습 목표 → 핵심 개념 → 단계별 설명 → 예시/시연 → 실습 → 요약 → 참고 자료 |

피치덱은 모르는 시장 규모·매출·고객 수를 임의로 채우지 않고 확인 필요로 표시한다. 차트는 데이터가 있는 경우에만 만든다. 각 장은 제목 하나와 핵심 주장 하나를 갖고, 세부 설명보다 시각적 비교·도식·차트를 우선한다.

### C. 시트 양식 — 카탈로그 선등록, 편집기는 후속

시트 양식도 같은 라이브러리에 등록하되, 공식·데이터 검증까지 하는 편집기는 문서/슬라이드 저장·편집 흐름 다음 단계로 둔다.

| ID | 우선순위 | 양식 | 탭/열과 자동 계산 |
|---|---|---|---|
| SHEET-01 | P1 | 업무일지 + 작업 추적 | 일자, 작성자, 프로젝트, 작업, 시간, 상태, 막힘, 다음 할 일; 주간 시간/상태별 개수 집계 |
| SHEET-02 | P1 | 프로젝트 트래커 | 작업, 담당자, 시작/기한, 상태, 우선순위, 선행 작업, 마일스톤; 지연/완료율 집계 |
| SHEET-03 | P1 | 예산·경비 관리 | 날짜, 항목, 예산, 실적, 결제자, 증빙 링크; 차액/합계 및 월별 요약 |
| SHEET-04 | P1 | 블로그 콘텐츠 캘린더 | 주제, 검색 의도, 키워드, 작성자, 초안/검수/게시 상태, 게시일, 커버, 결과 링크; 월별 상태 집계 |

수식은 템플릿 정의에 명시하고 테스트한다. AI가 사용자의 원본 시트를 읽어 수식을 추측해 덮어쓰지 않는다. 지역별 세금/통화·날짜 서식은 템플릿 변형으로 관리한다.

### D. 전문 검토가 필요한 양식

아래 양식은 라이브러리 유형으로 두되, 일반 P0 양식과 같은 기준으로 자동 게시하지 않는다.

- NDA/비밀유지계약
- 근로계약서·오퍼레터
- 프리랜서/용역/서비스 계약
- 이사회·주주총회 의사록과 결의서
- 고용/인사 정책 문서

필수 검수 메타데이터: 국가/관할 지역, 적용 대상, 공식 출처 또는 검수자, 검수일, 만료/재검토일, 사용 제한. 검수되지 않은 법률 문구는 최종 계약서로 표시하지 않는다.

## 4. 블로그 양식 메타데이터

AiDocX 블로그의 기존 필드 구성에서 일반화할 수 있는 메타데이터를 가져온다. 브랜드 이름과 앱 링크는 고정하지 않고 글을 게시할 채널의 설정값으로 받는다.

- 기본: slug, title, description, date, updatedAt, author, authorTitle, tags, lang
- 검색/카드: metaTitle, coverImage
- 자동 계산: wordCount, readingTime
- 본문 구조: 첫 답변/요약, 문제와 독자, 단계별 설명 또는 비교, 실제 예시, 체크리스트, FAQ, 결론, CTA
- 생성 전 입력: 대상 독자, 글의 목적, 키워드/검색 의도, 근거 문서, 게시 채널, CTA 목적
- 검사: 제목/설명 누락, 빈 소제목, 근거 없는 수치, 이미지 대체 텍스트 누락, 같은 문단의 반복

readingTime은 단어 수로 계산하고, 게시 채널 어댑터가 언어별 표시 규칙을 적용한다. 커버 이미지는 원본 파일로 보존하고 채널별 경로/크기는 export 단계에서 매핑한다.

## 5. 덱 양식 메타데이터와 구성

공통 메타데이터:

- deck_id, 제목, 사용 목적, 대상 청중, 언어, 예상 발표 시간
- 테마: 색상, 글꼴, 배경, 페이지 비율, 로고/푸터
- 원본/작성자/라이선스/버전/공개 범위
- 입력 데이터: 회사 소개, 지표 기간, 시장, 제품, 팀, 재무, 요청 사항
- 각 슬라이드: slide_id, 목적, 핵심 주장, 필수 데이터, 허용 컴포넌트, layout_id
- QA: 텍스트 넘침, 빈 컴포넌트, 출처 없는 수치, 차트 데이터 누락, 슬라이드 간 중복

기본 레이아웃은 표지, 한 문장 주장, 2~3열 비교, 타임라인, 큰 수치/KPI, 차트, 팀 프로필, 다음 단계/요청으로 만든다. IR 덱 구현에서 검증된 component 기반 접근을 참고하되, 원본 서비스의 스타일/브랜드/텍스트를 복사하지 않고 My Document Memory의 독립 테마를 둔다.

## 6. 템플릿 선택과 생성 규칙

1. 사용자가 “오늘 한 일 정리”, “투자자 업데이트”, “제안서”처럼 의도를 말한다.
2. 의도, 형식, 언어, 독자를 기준으로 후보 양식 최대 3개를 제안한다.
3. 각 후보를 고를 때 입력할 필드와 결과 예시를 먼저 보여준다.
4. 사용자가 양식과 참고자료를 따로 선택한다.
5. Planner가 섹션/슬라이드 아웃라인을 만든다. 사용자는 전체 초안 전에 순서와 범위를 승인하거나 고친다.
6. Writer가 승인된 구조를 채운다. 문서는 섹션 단위, 슬라이드는 장 단위로 결과를 편집기에 전달한다.
7. 작성 후 필수 필드·근거·페이지/슬라이드 넘침·수식·출처 표시를 검사한다.
8. 결과는 새 버전으로 저장하고 어떤 양식/자료 버전을 썼는지 기록한다.

공유 양식에서 가져오는 것은 구조와 스타일이다. 내용 사실은 사용자가 선택한 참고자료에서만 가져온다. 사용자가 원본 양식을 내 문서로 복사하면 원본 저작자·라이선스·버전의 연결을 유지한다.

| B. Slides 시드 | 덱 선택, 스토리라인 승인, 슬라이드 편집, PPTX/PDF 내보내기 | 스타트업 피치덱, 투자자 업데이트, 회사/제품 소개 |

| E. 외부 연결 | 사용자가 선택한 계정에 복사/생성 | Google Docs/Slides/Sheets, Notion |
